# Политика безопасности Агента Гермес (Hermes Agent)

Этот документ описывает протоколы безопасности, модель доверия и рекомендации по усилению защиты проекта **Агент Гермес**.

## 1. Сообщение об уязвимостях

В проекте Агент Гермес **нет** программы bug bounty. О проблемах безопасности следует сообщать через [GitHub Security Advisories (GHSA)](https://github.com/developer3000S/hermes-agent-rus/security/advisories/new) или по электронной почте **security@nousresearch.com**. Не открывайте публичные тикеты (issues) для уязвимостей безопасности.

### Детали сообщения
- **Заголовок и критичность:** Краткое описание и рейтинг CVSS.
- **Затронутый компонент:** Путь к файлу и диапазон строк.
- **Окружение:** Вывод `hermes version`, SHA коммита, ОС и версия Python.
- **Воспроизведение:** Пошаговое доказательство концепции (PoC).
- **Влияние:** Объяснение того, какая граница доверия была нарушена.

## 2. Модель доверия

Основное предположение заключается в том, что Гермес — это **персональный агент** с одним доверенным оператором.

### Доверие оператору и сессии
- **Один арендатор (Single Tenant):** Система защищает оператора от действий LLM, а не от злонамеренных «соседей» по системе. Многопользовательская изоляция должна происходить на уровне ОС/хоста.
- **Безопасность шлюза:** Авторизованные вызывающие стороны (Telegram, Discord и т. д.) получают равное доверие. Ключи сессий используются для маршрутизации, а не как границы авторизации.
- **Выполнение:** По умолчанию используется `terminal.backend: local` (выполнение прямо на хосте). Контейнерная изоляция (Docker, Modal, Daytona) включается по желанию.

### Одобрение опасных команд
Система одобрения (`tools/approval.py`) является ключевой границей безопасности. Команды терминала, операции с файлами и другие потенциально деструктивные действия требуют явного подтверждения пользователя. Режим одобрения настраивается через `approvals.mode` в `config.yaml`:
- `"on"` (по умолчанию) — запрашивает одобрение опасных команд.
- `"auto"` — автоматически одобряет после настраиваемой задержки.
- `"off"` — полностью отключает проверку (экстренный режим).

### Скрытие конфиденциальных данных (Redaction)
`agent/redact.py` удаляет паттерны, похожие на секреты (API-ключи, токены), из всего отображаемого вывода, прежде чем он попадет в терминал или на платформу шлюза. Это предотвращает случайную утечку учетных данных в логах чата.

### Навыки против MCP-серверов
- **Установленные навыки:** Высокое доверие. Эквивалентны локальному коду хоста; могут читать переменные окружения и запускать любые команды.
- **MCP-серверы:** Более низкое доверие. Процессы MCP получают отфильтрованное окружение. Пакеты, вызываемые через `npx`/`uvx`, проверяются по базе данных вредоносного ПО OSV перед запуском.

### Песочница для выполнения кода
Инструмент `execute_code` (`tools/code_execution_tool.py`) запускает сгенерированные LLM скрипты на Python в дочернем процессе, из которого удалены API-ключи и токены, чтобы предотвратить их кражу.

## 3. Вне рамок (не являются уязвимостями)

Следующие сценарии **не** считаются нарушениями безопасности:
- **Инъекция в промпт (Prompt Injection):** Если это не приводит к конкретному обходу системы одобрения или песочницы.
- **Публичный доступ:** Развертывание шлюза в открытом интернете без внешней аутентификации.
- **Доступ к доверенному состоянию:** Отчеты, требующие существующего доступа на запись к `~/.hermes/` или `.env`.
- **Поведение по умолчанию:** Выполнение команд на хосте при `terminal.backend: local` — это задокументированное поведение.

## 4. Усиление защиты и лучшие практики

### Файловая система и сеть
- **Песочница в продакшене:** Используйте контейнерные бэкенды (`docker`, `modal`, `daytona`) вместо `local`.
- **Права доступа:** Запускайте от имени пользователя без прав root; защищайте учетные данные с помощью `chmod 600 ~/.hermes/.env`.
- **Сетевой доступ:** Не выставляйте шлюз в открытый интернет без VPN или файервола.

### Навыки и цепочка поставок
- **Установка навыков:** Проверяйте отчеты Skills Guard перед установкой сторонних навыков.
- **Безопасность MCP:** Автоматическая проверка на вредоносное ПО OSV для пакетов `npx`/`uvx`.

## Обзор архитектуры

### Основной цикл

```
Сообщение пользователя → AIAgent._run_agent_loop()
  ├── Сборка системного промпта (prompt_builder.py)
  ├── Сборка аргументов API (модель, сообщения, инструменты)
  ├── Вызов LLM (API, совместимый с OpenAI)
  ├── Если в ответе есть tool_calls:
  │     ├── Выполнение каждого инструмента через реестр
  │     ├── Добавление результатов в разговор
  │     └── Возврат к вызову LLM
  ├── Если текстовый ответ:
  │     ├── Сохранение сессии в БД
  │     └── Возврат final_response
  └── Сжатие контекста при приближении к лимиту
```

## Добавление нового инструмента

Прежде чем писать инструмент, спросите: [не должен ли это быть навык?](#должно-ли-это-быть-навыком-или-инструментом)

Инструменты саморегистрируются в центральном реестре. Файл инструмента содержит схему, обработчик и регистрацию:

```python
"""my_tool — Краткое описание того, что делает этот инструмент."""

import json
from tools.registry import registry


def my_tool(param1: str, param2: int = 10, **kwargs) -> str:
    """Обработчик. Возвращает строку (часто JSON)."""
    result = do_work(param1, param2)
    return json.dumps(result)


MY_TOOL_SCHEMA = {
    "type": "function",
    "function": {
        "name": "my_tool",
        "description": "Что делает этот инструмент и когда его использовать.",
        "parameters": {
            "type": "object",
            "properties": {
                "param1": {"type": "string", "description": "Что такое param1"},
                "param2": {"type": "integer", "description": "Что такое param2", "default": 10},
            },
            "required": ["param1"],
        },
    },
}

registry.register(
    name="my_tool",
    toolset="my_toolset",
    schema=MY_TOOL_SCHEMA,
    handler=lambda args, **kw: my_tool(**args, **kw),
)
```

Не забудьте добавить инструмент в соответствующий список в `toolsets.py`.

## Безопасность

Гермес имеет доступ к терминалу. Безопасность важна.

- **Всегда используйте `shlex.quote()`** при вставке пользовательского ввода в команды оболочки.
- **Разрешайте симлинки** через `os.path.realpath()` перед проверками доступа.
- **Не логируйте секреты.** API-ключи никогда не должны попадать в лог.
- **Тестируйте на всех платформах.**
